# Kosmos operations

## Identity and access

Kosmos owns no passwords. Google authenticates users, and production admits only verified identities from the configured domains. The first approved user atomically becomes the organization owner. Later approved users start as members. Owners and administrators can assign owner, admin, member, or read-only viewer roles and can disable access.

Owners and administrators can also create named API credentials for workflows. Kosmos returns each plaintext token once and stores only its SHA-256 hash. Every request rechecks the stored credential, so revocation takes effect immediately. Read-only credentials cannot mutate data. Read-and-write credentials can use ordinary workspace APIs, but neither access level can manage members, credentials, Gmail, Google Voice, Cloudflare, Tiller, or other integrations. Store workflow tokens as secret values such as `KOSMOS_API_TOKEN`, never in repository variables, logs, or Trailwire messages.

Google Workspace access is a separate incremental grant for Gmail compose, Gmail metadata, Gmail send-as settings, and read-only Google Sheets. Refresh tokens are encrypted at rest with `KOSMOS_INTEGRATION_SECRET`, which is distinct from the web-only `KOSMOS_SESSION_SECRET`. The first split-key deployment migrates existing provider tokens from the session key before the web service accepts traffic. Later integration-key rotation intentionally invalidates saved provider tokens, attachment links, and every document signing link, so users reconnect Google afterward. Authenticated access to original and signed PDFs remains available. Register one OAuth redirect URI at `https://<host>/auth/callback`.

Owners and administrators can map each member to the primary address or an accepted Gmail send-as alias reported by Google. Kosmos rejects arbitrary or unverified addresses and enforces the saved mapping when sending. Existing Google connections must reconnect once to grant the send-as settings scope before aliases can be verified.

The shared Google Voice account is connected separately by an owner or administrator in Settings. This delegated grant may use a different Google identity than the administrator's Kosmos login and requests only Google Contacts access. Add the shared personal Google account as an OAuth test user while the consent screen remains in testing. Kosmos encrypts its refresh token separately from each member's Workspace grant, queues existing contacts after connection, and then mirrors contact creates, edits, and deletes through the private job service. Google Voice reads those Google Contacts; Kosmos does not automate the Voice calling or messaging UI.

## Public contact form

Submit JSON to `POST /api/v1/intake/contact` with `name`, `email`, and optional `company`, `phone`, `message`, and `source`. Include an empty `website` field as the honeypot. Kosmos validates size and email shape, deduplicates contacts by email, and saves each inquiry as a linked activity, including messages from existing contacts.

Production ingress must overwrite `X-Kosmos-Client-IP`, `X-Kosmos-Client-Time`, and `X-Kosmos-Client-Signature`. Sign `kosmos-intake-v1\n<unix-seconds>\n<canonical-IP>` with HMAC-SHA256 using the dedicated `KOSMOS_INTAKE_SECRET`, encoded as lowercase hex. The address uses canonical compressed IPv6 or IPv4, including unmapped IPv4-mapped addresses. The backend rejects missing, duplicate, or stale signatures outside a 60-second window and ignores caller forwarding headers. Shared Firestore quotas allow five attempts per IP per hour across all instances; database failures return 503. Expired `intakeRateLimits` documents are removed through `expiresAt` TTL.

## Gmail and Tiller

Outbound email always requires an explicit user action and an `Idempotency-Key` header. Retries with the same key return the saved delivery instead of sending twice. Kosmos sends the plain-text body as MIME base64 so transport line limits cannot introduce visible line breaks that were absent from the authored template. Inbox sync stores sender, subject, snippet, time, and thread identifiers only for known contacts. It does not store message bodies or replace Gmail.

## Account event history

Kosmos writes immutable events beneath an account when it can identify the relationship. This includes account and contact edits, opportunity changes, notes, calls, texts, reminders, documents, sent and received email, Cloudflare domains, and Tiller transactions. Account pages show the five newest entries and link to a cursor-paginated history with event-type filters. Google Voice handoffs record that the shared account was opened, not that a call or text was completed.

The timeline starts when this feature is deployed. It does not synthesize older history from mutable source records. External integrations use deterministic event identifiers so retries do not duplicate history. Interactive workspace mutations save the business record first and report timeline-write failures through structured telemetry rather than failing an already completed mutation.

Tiller import expects a header row with `Date`, `Description`, and `Amount`. `Merchant` and `Transaction ID` are optional. The default range is `Transactions!A:Z`. Stable transaction IDs make imports replay-safe. One deterministic contact match is accepted; zero or multiple matches enter the review queue.

Direct Tiller purchases are optional and independent of spreadsheet import. Create a Tiller application webhook for `https://<host>/api/v1/webhooks/tiller`, subscribe it to `order.paid`, and save the one-time `whsec_` signing secret in Kosmos Settings. Map immutable Tiller product IDs to Kosmos accounts there. Kosmos verifies the timestamped HMAC signature, ignores unmapped products, and derives transaction IDs from the event and order-line identity so Tiller retries cannot duplicate revenue.

## Cloudflare domains

Connect a dedicated user API token with Zone Read and Registrar Read access plus the 32-character Cloudflare account ID. Account-owned Cloudflare tokens do not currently support Registrar permissions. Kosmos encrypts the token, reads zones and registrations, and never calls a Cloudflare mutation endpoint. Linking a Cloudflare Registrar domain creates replay-safe reminders 30, 14, and 7 days before its expiry date. A zone registered elsewhere has no registrar expiry in Cloudflare, so the person linking it supplies that date.

Manual Gmail, Google Contacts, and Tiller synchronization requests return HTTP 202 after creating idempotent Cloud Tasks. They never wait for Google APIs in the browser request. Cloud Scheduler queues a synchronization pass at the top of every hour from 9 AM through 5 PM, Monday through Friday, in `America/New_York`. The private `kosmos-jobs` Cloud Run service executes tasks with a dedicated worker identity and a separate OIDC invoker identity. The queue dispatches one job at a time because Google requires mutations against one Contacts account to be serialized. Transactional record creation and effect-derived notification keys make overlapping manual and scheduled work replay-safe. Both web and worker services scale to zero. Investigate failed work in the Cloud Tasks queue first; provider failures return a retryable 5xx response and use bounded exponential backoff.

List endpoints default to 50 records and accept `limit` values through 100 plus the opaque `cursor` returned by the previous response. The browser follows cursors automatically so every record remains reachable without a desktop-only or mobile-only paging workflow.

Every contact mutation atomically records a durable synchronization intent, including deletion and account cascades. Dispatch failure leaves the intent pending. The worker removes it only after Google succeeds; scheduled and manual sync replay pending intents. Automatic recovery after exhausted queue retries waits for the next business-hours synchronization pass. Gmail traverses every inbox page without a search query and advances its checkpoint only after the complete pass succeeds.

Interactive document updates commit the revision snapshot and new document together. Clients can send `expectedRevision`; a stale edit returns 409 without changing either. The browser preserves the draft and offers the latest saved version for reconciliation.

## Managed documents

Use `PUT /api/v1/managed-documents/{sourceKey}` with a read-and-write API credential to publish one document from an external source. The source key accepts up to 128 letters, numbers, dots, underscores, or hyphens and deterministically identifies the Kosmos document. Send multipart form data with one `document` part containing `{"title":"...","body":"...","links":[]}` and zero or more repeated `files` parts.

The files in each request are the complete desired attachment set. Duplicate basenames are rejected. Changed files are replaced, omitted files are removed, and an identical retry returns the same document without creating another revision. File identifiers are deterministic by source key and basename. Storage and metadata cannot be committed atomically across GCS and Firestore, but every step is replay-safe and a retry converges after a partial provider failure. Publishers should serialize writes for a source key.

Document source uses ordinary Markdown. Images use `![Description](assets/kosmos/logo.svg)` and downloads use `[Download tokens](assets/kosmos/tokens.json)`. Kosmos resolves relative URL-path basenames against attachments on that document and leaves absolute URLs untouched. Existing `[[filename]]` embeds remain readable for compatibility.

## PDF signing

Signing requests use the existing organization scope, Firestore, and private object bucket. No additional signing service or signing secret is required. Authenticated users with write access, including write-enabled API credentials, upload and prepare requests through `/api/v1/signing-requests`. Read-only users can inspect and download them. Each request stores immutable prepared PDF bytes, prepared page dimensions, field placement, a revision, lifecycle events, and hashes. When preparation converts the upload, Kosmos also retains the raw uploaded bytes privately. Editing replaces the complete field set and is allowed only in `draft`.

Drafts accept up to ten recipients with stable IDs, names, and emails. Every field belongs to one recipient through `signerId`; each recipient needs a required signature field. Link creation freezes recipients and fields, sets the request to `pending`, and returns separate links that everyone can use immediately. The signing deadline is 1 to 90 days. A recipient token is `s1_<signer-id>_<MAC>`, with a 43-character base64url HMAC-SHA256 over `kosmos-signing-recipient-v1|<scope>|<request-id>|<signer-id>` using `KOSMOS_INTEGRATION_SECRET`. Existing single-recipient requests retain their 43-character token over `kosmos-signing-v1|<scope>|<request-id>`. Links are returned once in URL fragments; only token hashes are stored. Public access verifies the HMAC before Firestore lookup, then verifies the stored hash, expiry, and state.

The signing browser sends exactly one `X-Kosmos-Signing-Token` header to `/api/v1/signing/{id}` and its PDF and completion subroutes. Completion additionally requires `X-Kosmos-CSRF: 1`. Session cookies and workflow bearer credentials do not authorize these public routes. Do not put the signing token in URLs sent to the API, logs, analytics, or support messages. Integration-key rotation invalidates every existing signing link, including links to completed downloads; authenticated workspace users can still download the original and signed PDFs.

The link grants access to the prepared document and recipient metadata. Anyone holding it can sign; the email comes from the sender and is not independently verified. Signing captures the entered name and explicit consent, supplies date fields from the server's UTC clock, verifies the prepared PDF hash, and renders typed values plus an evidence page. The prepared copy remains unchanged. New requests record `originalSHA256` for the prepared copy, `uploadedSHA256` for the raw upload, and `signedSHA256` for the entire completed artifact. Conversion sets `flattened: true`; completion evidence includes both source hashes when they differ. The evidence page is an electronic signing record without a PKI certificate or an assertion of compliance equivalence to another provider.

Revision and status checks use a Firestore transaction. Each submission captures that recipient's name, values, signing time, consent, and session once. Compare-and-swap retries merge concurrent signatures and render from the immutable prepared PDF, preserving every previously accepted signature and its evidence. Each recipient retains their winning snapshot object and hash. A competing revocation can prevent further signing. The request remains pending until everyone signs; partial artifacts identify outstanding signers on every evidence page. Completed requests cannot be edited or revoked. Events record creation, link creation, individual signatures, final completion, and revocation, without claiming the recipient viewed the document.

Each recipient's original link expires 15 minutes after their own accepted signature, even when others have not signed yet. `accessExpiresAt` gives the current link's effective deadline. During that window, `pdf?completed=true` serves the latest partial or final artifact. Unsigned recipients cannot download signed artifacts through their signing link. Legacy completed requests derive the same 15-minute deadline from their immutable completion time. Expiry does not rewrite request status or prevent authenticated workspace access.

After all recipients sign, staff can call `POST /api/v1/signing-requests/{id}/download-link` with the current revision and `expiresMinutes` (1 to 10080, default 60). The returned download-only token uses `d1_<nonce>_<MAC>`, a 22-character base64url nonce and domain-separated HMAC over `kosmos-signing-download-v1|<scope>|<request-id>|<nonce>`. Creating another link atomically replaces the previous generated token hash and expiry. It preserves original signer deadlines, the PDF, and evidence. Download-only tokens require `completed=true`, cannot retrieve source PDFs, and cannot submit signatures. Creation is limited to 20 links per organization per minute.

New completions record an optional `session` snapshot containing `ipAddress`, `userAgent`, `capturedAt`, `source`, and available `city`, `region`, and `country`. This is captured at submission and saved with the winning completed PDF in the same Firestore transaction. Retries return the original saved snapshot; older completed records remain without it. The browser User-Agent is self-reported and location is an approximate IP-based estimate, not verified identity or precise physical location. The signing page discloses this collection before consent.

Production completion accepts session metadata only through the authenticated Cloudflare ingress envelope. Cloudflare supplies city, region, and country from `request.cf`; the envelope bounds User-Agent to 512 UTF-8 bytes and city and region to 128 bytes each. Country is two uppercase ASCII letters or empty. The Worker replaces control and formatting characters, line and paragraph separators, and invalid Unicode characters with spaces, trims the values, and truncates at a UTF-8 character boundary. Direct local operation records the socket peer address and normalized User-Agent with `source: direct`, without trusting forwarded addresses or location headers.

For `POST /api/v1/signing/{id}/complete`, the ingress overwrites `X-Kosmos-Signer-Evidence` and `X-Kosmos-Signer-Signature`. Evidence is unpadded base64url UTF-8 JSON with exactly `version: 1`, `ipAddress`, `userAgent`, `city`, `region`, `country`, and `timestamp` (Unix seconds). All keys are required; unavailable location strings are empty. Sign `kosmos-signing-evidence-v1\nPOST\n<path>\n<encoded-evidence>` with HMAC-SHA256 using the existing `KOSMOS_INTAKE_SECRET`, encoded as hexadecimal. The signature binds the evidence payload and exact completion path. The backend rejects duplicate headers, encoded evidence over 4096 bytes, malformed or duplicate JSON fields, noncanonical IPs, unsupported versions, and timestamps more than 60 seconds from its clock. The stored `capturedAt` is the verified edge timestamp.

Deploy the compatible ingress Worker before the application that requires this envelope. The existing shared intake secret provisioning and environment module remain sufficient. Missing, invalid, or stale ingress evidence returns 403 with `signing_session_unverified` before a new completed artifact is written. The JSON completion body cannot supply session evidence. Already completed retries return their saved evidence without recapturing it.

Session details belong to the retained business record and signed PDF, never logs, traces, or analytics. Public recipient JSON contains only that recipient's fields and personal evidence, plus the other recipients' names and signing progress. Shared partial and final PDFs include accepted participants' signing records, as disclosed before consent. There is no view tracking, GPS, postcode, fingerprinting, cookie, or session-token capture for this audit. Normalized UTF-8 metadata is retained exactly; the PDF escapes characters outside Windows-1252 and adds signing-record pages as needed. See [ADR 0019](../adr/0019-record-completion-session-evidence-from-authenticated-ingres.md) for the trust boundary and [ADR 0021](../adr/0021-collect-parallel-signatures-with-recipient-scoped-capabiliti.md) for parallel signing.

Shared Firestore quotas permit 20 uploads per organization per minute, 120 public calls per request per minute, and 10 pending completion attempts per request per minute. Each process admits only one upload before buffering its body; competing uploads fail immediately with 429 and `Retry-After: 1`. Quota failures also return 429 with `Retry-After`; storage failures fail closed. Invalid or missing tokens return 404. Correct tokens for expired or revoked requests return 410. Stale revisions and incompatible states return 409.

Preparation first checks the existing strict PDF rules. Already compatible inputs remain byte-identical. Other supported inputs are rendered server-side with go-pdfium's embedded PDFium WebAssembly module hosted by wazero, without filesystem mounts, network access, or document action execution. Kosmos renders visible forms and annotations into a fresh image-only PDF at 200 DPI with JPEG quality 95. Converted document bodies lose selectable text, vector detail, and document-level accessibility structure. Review the prepared preview before sending it for signature.

Limits are 10 MiB for uploads and prepared output, 50 pages, and at most eight million rendered pixels per page. Preparation is limited to one concurrent job per process with a 45-second deadline including queue wait and 192 MiB of WebAssembly linear memory. Encrypted PDFs, XFA, unsupported or unrenderable form states, malformed inputs, and oversized conversions are rejected. Export a simpler unencrypted PDF and upload a new request when preparation fails. Prepared page dimensions remain limited to 1 to 40 inches. Existing parser limits also bound decoded content, image size, object count, and nesting.

The default PDF download serves the prepared signing copy. Authenticated `GET /api/v1/signing-requests/{id}/pdf?uploaded=true` serves the raw upload; public signing links cannot access it. `uploaded=true` on a public download or combined with `completed=true` returns 400. Preserve the uploaded, prepared, and signed objects together when restoring a converted request, and verify each recorded hash.

Windows-1252 signing text without control characters is supported. Fields must measure at least 20 PDF points wide and 15.6 points high, in addition to the normalized size limits. Link creation checks that date fields and the supplied recipient name fit before locking the request. If a later signer value will not fit at a readable font size, shorten it or ask the sender to prepare a new request with a larger field.

For a lost, leaked, expired, or incorrectly prepared signing link, revoke the pending request and create a new request. There is no signing-token recovery, field editing after link creation, or signing-deadline extension. Completed documents can receive fresh download-only links. Kosmos does not send signing emails automatically.

Delete draft, completed, or revoked documents through `DELETE /api/v1/signing-requests/{id}` with `{revision, confirmed: true}`. Pending documents must be revoked first. A Firestore transaction removes the live request and creates a private `signingCleanup` outbox containing the uploaded, prepared, latest signed, and all committed recipient snapshot objects. All links stop working immediately. The scheduler dispatches `signing.cleanup` jobs independently of provider integrations. Successful object deletions are persisted individually; retention failures retry after one hour. Production's existing 30-day retention remains in force, so removing a document from the workspace does not promise immediate physical erasure.

If completion reports a transient failure, reload before retrying. Object writes and Firestore cannot commit together. Failed artifact attempts enter delayed cleanup with an ownership check before deletion; current and historical recipient snapshots must be retained. Cleanup failures are logged without document or session data. An outage that prevents recording the cleanup obligation can leave an orphan requiring recovery. Never delete an object based only on a failed HTTP response. Read authoritative metadata, preserve every referenced object, and verify recorded hashes before removing an unreferenced attempt. Restore metadata and matching object generations together. There is no automatic deletion merely because a link expires. See [ADR 0020](../adr/0020-separate-signing-and-download-access-and-persist-document-cl.md).

## Files, retention, and recovery

Attachments are private objects. Each upload is limited to 10 MB. Documents accept PDF, Markdown, plain text, JSON, CSS, SVG, JPEG, PNG, or WebP. Contact and account photos remain limited to JPEG, PNG, or WebP. Receipt records must link to a cost. Downloads require both an authenticated identity and an application-signed URL that expires after 15 minutes.

Production buckets prevent public access, use uniform access control, retain object versions, and apply lifecycle cleanup. Firestore production enables point-in-time recovery. CSV exports for contacts and costs provide a portable copy before deletion or migration. Spreadsheet formula-like text receives a leading tab in the export; stored values remain unchanged. Restore by selecting the desired Firestore recovery point and object generation, then verify organization ownership before serving traffic.

## Deployment and observability

Publish `infra/modules/environment` to the Spacelift private module registry, then pin that exact tested version in the configurations repository. Never float production to the latest module. Quill is the only application release path. The release workflow tests the application, builds the React bundle, uses GoReleaser to produce Linux binaries, and then assembles, signs, attests, and publishes the image from those artifacts. Spacelift deploys only after the module version is active, the configurations pin is committed, and the complete plan has been reviewed.

Backend tracing uses standard `OTEL_EXPORTER_OTLP_*` variables. The secret value for `OTEL_EXPORTER_OTLP_HEADERS` must use the full environment-header format, including the header name, such as `Authorization=Basic <credential>`. Browser telemetry uses `KOSMOS_FARO_URL`; production accepts only the `https://kosmos.nerdswhofish.com` origin. The managed Grafana dashboard covers request volume, status, p95 latency, backend and frontend errors, and job activity. Grafana alerts on production browser errors, while Cloud Monitoring alerts on public downtime, web and worker 5xx responses, scheduler dispatch failures, and sustained queue backlog. Telemetry must never include tokens, message bodies, receipt contents, or raw customer data. Production verification checks health, anonymous access denial, responsive login behavior, Faro ingestion, Cloud Run logs, asynchronous task execution, and a correlated Grafana trace before accepting the release.
